## 1. 개요

**My Tasks**는 설치와 서버 없이 브라우저에서 `index.html`을 열기만 하면 쓸 수 있는 개인용 할 일 관리 앱이다. 데이터는 브라우저의 localStorage에 저장된다. 화면 문구는 한국어로 되어 있다.

이번 작업 주기에는 두 가지를 추가했다.
1. **키워드 기반 자동 카테고리 분류:** 할 일을 입력하면 카테고리가 자동으로 정해진다.
2. **데스크톱 전용 화면(`web_version`):** 모바일 기준의 600px 카드 화면을 데스크톱의 화면 전체를 쓰는 레이아웃으로 확장했다.

## 2. 배경과 문제

| 문제 | 근거 |
|---|---|
| 할 일을 추가할 때마다 카테고리를 직접 골라야 해서 번거롭다 | 입력 흐름이 "카테고리 선택 → 입력 → 추가" 3단계 |
| 데스크톱에서는 화면 가운데 600px 카드만 쓰여 양옆 공간이 낭비된다 | 사용자 제공 스크린샷 `1(11.10).png` |
| 데스크톱에서 목록을 스크롤하면 진행률·필터·입력창이 화면 밖으로 사라진다 | 한 열 구조 |

## 3. 목표와 비목표

### 목표
- **G1.** 일반적인 할 일 문장의 카테고리를 입력 중에 자동으로 정해서, 카테고리를 직접 고르는 횟수를 줄인다.
- **G2.** 사용자가 직접 고른 카테고리는 자동 분류보다 항상 우선한다.
- **G3.** 가로 1024px 이상 화면에서는 창 전체를 쓰는 2단 레이아웃을 제공한다.
- **G4.** 데스크톱에서 스크롤해도 요약·필터·입력·검색을 계속 쓸 수 있다.
- **G5.** 기존 기능(드래그 정렬, 되돌리기, 가져오기/내보내기, 단축키, 다크 모드, 접근성)이 두 화면 모두에서 그대로 동작한다.
- **G6.** 설치 없이 웹 주소로 두 화면에 접근할 수 있게 GitHub Pages로 배포한다.

### 비목표
- 서버 동기화, 로그인, 여러 기기 간 공유
- AI·형태소 분석 기반 분류. 이번에는 키워드 사전만 쓴다.
- 기존 항목 수정이나 가져오기 시 카테고리를 자동으로 바꾸는 것. 이미 정한 카테고리가 사용자 모르게 바뀌는 것을 막기 위해서다.
- 목록을 여러 열(그리드)로 배치하는 것. 드래그 정렬이 한 열을 전제로 하기 때문이다.

## 4. 사용자

- **주 사용자:** 업무·개인·공부 할 일을 한곳에서 관리하는 개인 사용자 1명
- **사용 환경:**
  - 데스크톱: Windows, Chrome. 주 해상도는 1366×768부터 1920×1080까지다.
  - 모바일 브라우저

## 5. 기존 기능 (변경 없음, 회귀 금지)

| 영역 | 기능 |
|---|---|
| 할 일 | 추가, 완료 체크, 인라인 수정, 삭제, 중복 입력 경고("그래도 추가") |
| 분류 | 카테고리 3종(업무·개인·공부), 카테고리 필터(Alt+1~4) |
| 탐색 | 검색(하이라이트 표시), 정렬 5종: 완료 상태순, 직접 정렬(드래그), 생성일 최신순, 생성일 오래된순, 카테고리순 |
| 현황 | 전체 진행률, 카테고리별 진행률, 오늘 추가 개수, 남은 개수, 응원 문구, 오늘의 격언 |
| 데이터 | localStorage 자동 저장, 다른 탭과 동기화, 되돌리기(최대 10개), JSON 내보내기/가져오기(병합·대체, 백업 옵션) |
| 편의 | 다크 모드(Alt+D), 단축키(Alt+N, Ctrl+Z), 키보드로 순서 바꾸기(↑/↓) |
| 접근성 | 스크린 리더 알림, 포커스 관리, 네이티브 다이얼로그, 바로가기 링크 |

## 6. 신규 기능 요구사항

### 6.1 키워드 기반 자동 카테고리 분류

| ID | 요구사항 | 우선순위 |
|---|---|---|
| AC-1 | 새 할 일 입력창에 글자를 입력할 때마다 카테고리 선택값을 자동으로 바꾼다. | 필수 |
| AC-2 | 키워드는 단어의 일부만 같아도 인식한다. 예: "회의를"에서 "회의"를 인식한다. 한국어는 조사가 붙기 때문이다. | 필수 |
| AC-3 | 영문 키워드는 대소문자를 구분하지 않는다. | 필수 |
| AC-4 | 일치한 키워드가 가장 많은 카테고리를 고른다. 동점이거나 일치가 없으면 자동으로 정하지 않고, 사용자가 마지막으로 고른 카테고리를 쓴다. | 필수 |
| AC-5 | 자동으로 분류되면 근거를 보여준다. 입력창 아래에 "자동 분류: 업무 (‘회의’)"를 띄우고, 카테고리 선택 박스 테두리를 강조색으로 바꾼다. | 필수 |
| AC-6 | 입력 중에 사용자가 카테고리를 직접 바꾸면, 입력창을 비우거나 할 일을 추가할 때까지 자동 분류를 멈춘다. | 필수 |
| AC-7 | 할 일을 추가한 뒤에는 카테고리 선택이 사용자가 마지막으로 직접 고른 값으로 돌아간다. | 필수 |
| AC-8 | 한 글자 키워드(예: '집', '책')는 쓰지 않는다. 다른 단어 안에 들어가 잘못 분류될 수 있기 때문이다. | 필수 |
| AC-9 | 자동 분류는 새 할 일 추가 폼에만 적용한다. 인라인 수정과 가져오기에는 적용하지 않는다. | 필수 |
| AC-10 | 키워드는 코드 상수 한 곳(`CATEGORY_KEYWORDS`)에서 고칠 수 있다. | 필수 |

**예시**

| 입력 | 결과 |
|---|---|
| 내일 회의를 준비 | 업무 |
| 토익 단어 암기 | 공부 |
| 마트 장보기 | 개인 |
| 영어 회의 | 동점이라 변경하지 않음 |
| constructor | 분류하지 않음 |

### 6.2 데스크톱 레이아웃 (`web_version`)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| DL-1 | 가로 1024px 이상에서는 창 전체를 쓰는 2단 레이아웃을 쓴다. 왼쪽은 사이드바, 오른쪽은 작업 영역이다. | 필수 |
| DL-2 | 사이드바에는 제목, 남은 개수, 테마 토글, 격언, 진행률, 세로 필터 메뉴, 목록 관리 버튼, 단축키 안내를 둔다. 사이드바는 스크롤해도 고정된다. | 필수 |
| DL-3 | 작업 영역 맨 위의 입력 폼과 검색·정렬 바는 스크롤해도 화면 위에 남는다. | 필수 |
| DL-4 | 1024px 미만에서는 기존 한 열 화면과 같은 순서와 모양으로 보인다. | 필수 |
| DL-5 | 스크롤이나 포커스로 이동한 항목이 상단 고정 바 밑에 가려지지 않는다. 대상은 중복 강조, 키보드로 순서 바꾸기, Shift+Tab 이동이다. | 필수 |
| DL-6 | 드래그하는 항목은 고정 바 위에 보이고, 위로 끌면 고정 바 바로 아래에서 자동 스크롤이 시작된다. | 필수 |
| DL-7 | 상단 바 높이가 바뀌어도 DL-5와 DL-6이 자동으로 맞춰진다. 직접 값을 고칠 필요가 없어야 한다. | 필수 |
| DL-8 | 화면 높이가 860px 이하인 노트북에서도 사이드바가 넘치지 않는다. 이때 격언은 숨기고 간격을 줄인다. | 권장 |
| DL-9 | 아주 넓은 화면에서는 입력창과 목록의 최대 너비를 1,100px로 제한하고 가운데에 둔다. | 권장 |
| DL-10 | 1440px 이상에서는 사이드바 너비를 380px로 넓히고 여백을 늘린다. | 권장 |
| DL-11 | 기본판과 데스크톱판은 같은 localStorage를 쓴다. 한쪽에서 추가한 할 일이 다른 쪽에도 보인다. | 필수 |

## 7. 비기능 요구사항

- **의존성 없음:** 빌드 단계, 패키지 관리자, 외부 라이브러리를 쓰지 않는다.
- **성능:** 할 일이 최대 5,000개여도 입력·스크롤이 매끄러워야 한다. 키 기반 렌더링과 `content-visibility`를 쓴다.
- **안전성:** 사용자 텍스트는 `textContent`로만 넣는다. 저장 실패 시 오류 알림을 띄우고, 손상된 데이터는 백업한다.
- **테마:** 모든 색은 CSS 변수로 지정한다. 라이트·다크 모두 지원한다.
- **접근성:** 키보드만으로 모든 기능을 쓸 수 있다. 스크린 리더 알림을 유지하고, 모션 줄이기 설정을 존중한다.

## 8. 성공 기준

| 기준 | 측정 방법 | 결과 |
|---|---|---|
| 자동 분류 정확도 | 6.1 예시를 포함한 헤드리스 테스트 | 통과 |
| 직접 선택 우선 | 입력 중 직접 변경 → 추가 → 잠금 해제 확인 | 통과 |
| 고정 바에 가려짐 없음 | `scrollIntoView` 후 항목 위쪽과 바 아래쪽 사이 간격 ≥ 0 | 바 아래 7~8px |
| 바 높이 자동 추종 | 바 높이를 169px에서 204px로 키운 뒤 스크롤 여백 확인 | 177px → 212px |
| 드래그 자동 스크롤 | 끝 항목을 바 아래로 끌기 | 위로 스크롤되고 순서가 바뀜 |
| 짧은 화면 | 1440×820에서 사이드바 넘침 | 0px |
| 회귀 없음 | 추가, 자동 분류, 필터, 진행률 (두 화면 모두) | 오류 없음 |

## 9. 남은 과제와 위험

- `script.js`가 두 폴더에 같은 내용으로 따로 있어, 고칠 때 두 곳을 모두 바꿔야 한다([TASK.md](TASK.md) T-20).
- 키워드 사전 방식이라 문맥을 이해하지 못한다. 예를 들어 "회의실 청소"는 동점이라 분류되지 않는다.
- 실제 마우스·터치 드래그는 헤드리스 Chrome의 합성 이벤트로만 검증했다.
- GitHub Pages(공개 저장소)에 배포하면 코드와 문서를 누구나 볼 수 있다. 또 사이트의 데이터는 로컬 파일로 열 때의 데이터와 공유되지 않는다([TRD.md](TRD.md) 8절).
